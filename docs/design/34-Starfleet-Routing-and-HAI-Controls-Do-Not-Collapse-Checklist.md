## A. The matrix — how Starfleet decides (canonical: [[34-CHARTER]] § "Central design principle" + § "End state"; [[34-Phase-7-Placement-Policy-Design]] step 1)

- [ ] **A1. All three factors are weighed TOGETHER, per request.** Speed, cost and quality at the same time — never one
  lens per request, never one lens per request type, never one lens per tier. the owner: *"It's not just one lens that you
  look through… our Star Fleet command is supposed to use all three lenses, which is why I've been saying we need to
  have an LLM assist for our Kirk and Spock. We need it based on all three at the same time which is why it's been a
  whole thing for McCoy to be able to actually advise based on all three of these factors."* Earlier: *"These are
  dynamic according to the matrix of speed, quality, and cost."*
- [ ] **A2. There are exactly THREE lenses** — `fastest`, `least_energy`, `best_quality` (the owner 2026-10-07: *"there's three
  factors speed cost, and quality"*). Do not add a fourth to approximate the trade-off. The weighing across them is
  area C (evolve `scheduler.place` / `energy.py`: urgency, deadline, energy trough, contention, ETA) plus McCoy's
  PLACEMENT advice — not a lens.
- [ ] **A3. The menu IS the matrix**, with many inputs. the owner: *"The menu is the matrix so it has multiple inputs. It
  matters for speed time. Electricity cost […] everything that I've been telling you about over the past two
  months."* The charter's rule: *"Use the least expensive source of compute and intelligence that reliably satisfies a
  task's quality + time requirements, while accounting for verification, energy, resource contention, and
  escalation"*; one rule at every layer: the cheapest ACCEPTABLE worker on the menu.
- [ ] **A4. Chat's PRIMARY need is speed — not its only need.** the owner: *"one of the primary things for Chad [chat] is
  going to be speed, which is what makes it chat. I did not say that the only thing for Chad is speed… we cannot just be

## B. The definitions — never redefine them (canonical: [[34-Phase-7-Placement-Policy-Design]] step 1)

- [ ] **B1. SPEED = the time the user waits**, from the request arriving to the answer on their screen — a cold load,
  a re-read, a wake all count HERE — **AND** the time until the model first shows something: *"We are counting the
  thinking box that is piped in as interactivity so that the user that is waiting on a chat is still seeing stuff. It is
  not only the time to answer final. It is also the time until the model starts thinking and shows stuff."*
- [ ] **B2. Users differ in which half of speed they mind:** *"Some users will be more turned off by a long time overall,
  but other users will be fine if a long time is going on and they're able to see the thinking process as well."*
- [ ] **B3. COST = literal electricity** (J/solve → money): *"Expense has always been literal electricity expense for
