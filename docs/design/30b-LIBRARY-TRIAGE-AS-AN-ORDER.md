## The order — the submitter names DOCS, nothing else

```json
{"spec": {"name": "triage-stage8-batch1",
          "docs": ["LLM-Project/…md", "…"],
          "rubric": "Library-Section-Triage-Rubric.md",
          "out": "State/library-triage/",
          "steps": [ {"step": "extract",  "requires": ["triage.extract.v1"]},
                     {"step": "classify", "requires": ["triage.rubric.v1"], "after": "extract"} ]}}
```

One order. The fleet decomposes it with the EXISTING chain machinery (`compose_steps`,
`after_ids`); each step lands on whichever factory declares that step's capability. Intake is
untouched — the capability-gap refusal was proven live 2026-08-21.

## Step 1 — `extract` (CPU work; Fellowship AND x86 both declare it — the owner: "why not both?")

Deterministic text work, no model: read the named docs, split into sections at headings, then the
**rules lane** — pattern-based pre-classification and claim mining:

* **credential** — secret patterns / entropy (password:, key=, tokens, base64 runs);
* **record** — dated-closure markers (`CLOSED 20xx-`, `measured 20xx-`, strikethrough+date,
  benchmark tables naming their instrument);
* **narrative** — first-person density, past-tense/story markers, quoted-dialogue patterns;
* **VERIFY claim mining** — present-tense count claims ("all five", "N of M"), IPs, hostnames,
  versions, "runs on / wired into". High-recall extraction is what regexes are for; this may
  beat a model outright on the VERIFY axis (hypothesis — the gold arms decide).

Sections the rules settle at high confidence ship labeled with evidence; the rest go on the
residual list. Deliverable: section inventory + settled labels + mined claims + residual, per the
existing chained-order artifact conventions (`order.after_exists`).

**Both factory families declare `triage.extract.v1`** and Spock routes per order: the Fellowship
(48 always-on cores via Tolkien's fan-out — extract can run without waking one x86 box, which
composes with the sleep-the-x86-boxes plan) and the x86 CPU factories (`order.compute` precedent)
for redundancy when the Fellowship is mid-job.

## Step 2 — `classify` (GPU foundries)

Only the residual. Per section: one call to the factory's LOCAL ollama — rubric + section text,
**JSON schema in `format`** (structured outputs; read `content or thinking`), no tools, no RAG,
no chat system prompt. Serving model recorded per row; a row served below the required tier is
refused and requeued, never graded as the asked-for tier. Merges rules-settled + model rows and
ships ONE candidate JSONL per order (`section, lines, TIER, VERIFY, quote, action,
decided_by: rule|model, model`) + completion DM. Product = the candidate list; raw model answers
are byproducts beside it.
