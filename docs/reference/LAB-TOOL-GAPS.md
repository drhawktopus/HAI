# LAB TOOL GAPS — the tools we still need to build so the lab runs as intended (register)

Started 2026-10-05 at the owner's request: *"if this exposes a gap in the tools that we have already built then it's not a
bad idea for us to start making a list of tools that we need to create in order to let things run as we intend."*

**How to use this register.** A gap goes here the moment someone does by hand something a tool should do, or finds
that a capability is missing or unwired (doctrine class 17). One row per gap, in plain terms: what is missing, what
it cost or risked, what the tool should do, and its status. When a gap is closed, MOVE the row to
`Archive\lab-tool-gaps-closed-<date>.md` with its closing evidence (doctrine 21: the live register holds open gaps
only). A one-off fix with no tool behind it is not "closed"; a bug fix belongs in the component's doc, not here.
