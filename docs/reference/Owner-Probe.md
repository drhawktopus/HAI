# The the owner Pass - Adversarial Supervisor Probe

**Canonical shared copy:** 2026-08-19. Promoted from Claude memory
a private note of the owner's adversarial probes, which was mined from the owner's pushes across journals,
doctrine, and chats. The private memory is provenance, not authority. This shared document is the
review surface for Claude, Codex, HAI, and future supervisors.

## Application rule

Run all 23 probes against:

- every worker plan or report before accepting or relaying it;
- every deploy, promotion, destructive action, or authoritative documentation edit;
- every supervisor conclusion before it reaches the owner.

A pointer to this file is not the pass. Open it, run it, and record which probes were applicable.
A claim that breaks one probe goes back with that probe and the required evidence. Apply the same
standard to findings, retractions, celebrations, and convenient clean results.

## The 23 probes

1. **Inversion sniff.** If a result reverses a known ordering or baseline, suspect the instrument,
   configuration, identity, or measurement before accepting the surprise.
2. **Where is the gate?** Every recurring incident implies a missing, blind, unwired, or unenforced
   guard. Find the owning gate and cross-cut the fix.
3. **Already exists / library first.** Before deriving or building, follow indexes and pointers to
   the established mechanism, research, manual, and prior result.
4. **Placement / ownership.** Identify which component or order-taking desk should own and execute
   the work. A session should not become a parallel system.
5. **Dumb-direct path.** Challenge accidental complexity with the simplest established path that
   satisfies the actual requirement.
6. **No lame answers.** Do not disguise resignation as realism. Prove the hard path is closed; park
   it explicitly only when the owner chooses to.
7. **Finish same-pass.** A real gap is fixed, documented, and cross-cut in the same pass or parked
   explicitly by the owner.
8. **Survives its own citations?** Test the claim against the worker's own docstrings, design,
   runbook, prior assertions, and cited evidence.
9. **Convenient-conclusion distrust.** Findings that excuse work, dismiss alerts, declare absence,
   or make the task easier receive extra scrutiny.
10. **Why is the lab not doing this?** Check whether HAI, Kirk/Spock, a factory, an existing tool,
    or another lab system should perform the manual assistant work.
11. **Plain observed mismatch.** State what was promised and what was actually observed without
    smoothing the difference.
12. **Vocabulary precision.** Split overloaded terms and use exact entity names; ambiguous words
    cause ownership and routing errors.
13. **Statuses, not timeouts.** Ask the worker or owning system for a verdict. Clocks are fallback
    heartbeats, not completion signals. Preserve an explicit inconclusive state.
14. **Form-of-verification challenge.** Match the proof to the claim: existence is not deployment,
    deployment is not in-force execution, a green unit suite is not a live guard, and a narrow path
    check cannot prove universal absence.
15. **Full context and recency.** Read the complete relevant exchange and prefer the newest
    correction. Snippets and cover letters do not override later worklogs or live state.
16. **Authority check.** Identify whose control surface this is and what the owner actually authorized.
    Do not create permissions, gates, stops, or scope expansion by inference.
17. **Quote the owner or it was invented.** Attach the owner's words to requirements and policy decisions.
    Do not round musings into specifications.
18. **Right-class generalization.** Capture the project-independent failure class, not only the
    current project's costume.
19. **Protect hard-won state.** Raise the bar around configurations, results, and systems that took
    substantial work to establish.
20. **Fix + document + cross-cut.** A fix is incomplete until the authoritative docs are updated
    and peer consumers or sibling hosts are checked.
21. **The ask, compressed.** Present the owner with the actual decision surface and action required,
    not a narrative that makes him excavate it.
22. **Ideology pull.** Check choices against the lab's stated end goal, architecture, autonomy,
    ownership, and operational ethos.
23. **Entity precision.** Names are load-bearing. Fleet, Fellowship, Kirk, Spock, Tolkien, factories,
    desks, hosts, artifacts, and users must not be blurred together.

## Evidence and certainty

Label material claims using the owner's two-way certainty convention:

- **Measured:** directly observed with an appropriate instrument.
- **Document-verified:** supported by the authoritative current library source.
- **Inferred:** conclusion from named evidence; state the inference.
- **Guessed:** unverified working hypothesis; never publish it as state.

Interpret the owner's own certainty literally: wondering invites measurement; `I think` is a hypothesis;
`fairly certain` is a high prior requiring exhaustive checking before contradiction; a flat
assertion about his own lab means hunt for the assistant's error first.

## Escalation posture

Catch the mismatch, name the doctrine class or probe, demand the bounded same-pass correction, and
verify the result. Do not make the owner perform the proof or operate routine lab machinery.
